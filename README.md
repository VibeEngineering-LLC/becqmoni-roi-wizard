# Конструктор ROI и наборов нуклидов для BecqMoni

**Live:** https://vibeengineering-llc.github.io/becqmoni-roi-wizard/

Сборка ROI-конфигураций [BecqMoni](https://github.com/Am6er/BecqMoni) (формат `120920`)
и наборов нуклидов (NuclideSet) из ядерных данных IAEA: выбор изотопов, семейств и цепочек
распада → отбор γ/X/ХРИ-линий и вторичных пиков → адаптация под разрешение детектора →
экспорт `.xml`.

Инструмент существует в двух видах:

- **веб-страница** (этот репозиторий, ссылка выше) — автономная, работает и с `file://`;
- **модуль для самого BecqMoni** — [`integration/`](integration/README.md): тот же расчёт
  на C# (.NET Framework 4.8, WinForms), только результат пишется не в файл, а прямо в
  `ROIConfigManager` и `NuclideDefinitionManager` приложения.

*Web wizard that builds BecqMoni ROI configuration files from IAEA nuclear data:
pick nuclides, families or decay chains, select γ/X-ray/XRF lines and secondary peaks,
merge lines under the detector resolution, export ready-to-use `.xml`.*

## Возможности

- **База**: 121 нуклид (снимок IAEA Live Chart of Nuclides API, ENSDF) — γ-линии и рентген
  распада, T½, ветвления; 8 семейств с кодами по **ANSI N42.34** — POPULAR, NORM (ЕРН),
  MED (медицинские), IND (техногенные и калибровочные), SNM (делящиеся материалы), плюс вне
  стандарта FISS (осколки деления), NAA (активационные), WASTE (ОЯТ и РАО); 3 цепочки распада
  (U-238, Th-232, U-235). В русском интерфейсе основное название — российское, код в скобках.
- **Выбор**: живой поиск (ввод сужает список; в строке — семейства, T½, число γ/X-линий,
  клик добавляет) и комбобокс «Группа» — семейства и ряды распада одним списком, с кнопкой
  **(i)** (расшифровки кодов и стандарт).
- **Три варианта добавления** — одинаковые для поиска и для группы:
  «Добавить» / «добавить все» — только выбранное, каждый нуклид сам по себе;
  «+ линии семейства» / «одним» — линии дочерних под именем родителя (один изотоп в списке);
  «+ цепочкой» / «цепочкой» — дочерние отдельными нуклидами с пометкой родителя
  («Pb-214 (U-238)», «Tc-99m (Mo-99)»). Родитель в скобках — то, по чему BecqMoni опознаёт
  цепочку при связке амплитуд. Пары вне ЕРН-рядов: Mo-99→Tc-99m, Ce-144→Pr-144,
  Ba-140→La-140, Zr-95→Nb-95, Te-132→I-132, I-133→Xe-133.
- **ХРИ материалов защит и детекторов**: Fe, Cu, Cd, Sn (защита/конструкции), Te, I, Ba, La
  (кристаллы CdZnTe/NaI/LaBr₃), W (коллиматор), Pb (защита). Энергии NIST/Bearden,
  интенсивности относительные (Kα1 = 100). La и Ba идут парой: у LaBr₃(Ce) есть собственная
  активность La-138 и рентген Ba от её K-захвата.
- **Вторичные пики** (расчёт по выбранным γ): рассеяние назад (BS), комптон-край (CE),
  вылет 511/1022 (SE/DE), вылет I-K (NaI), аннигиляция 511, **каскадное суммирование**
  (SUM = E1+E2, напр. Co-60 → 2505) и **наложение** (PU = 2×E, напр. Cs-137 → 1324).
- **Адаптация под разрешение детектора (IDWin)**: слияние линий, которые детектор не
  разрешит. Порог локален для каждой группы: FWHM(E) = R₆₆₂·√(662·E)/100 — модель для
  **сцинтилляторов** (NaI(Tl) 6.5–8 %, CsI(Tl) 8–10 %, SrI₂(Eu) 3–3.5 %, LaBr₃ 2.7–3.3 %
  на 662 кэВ). Для HPGe закон √E занижает FWHM на низких энергиях (нужен √(a+bE) —
  не реализован). Три критерия:
  - **предел Sparrow**, ΔE < 0.85·FWHM (= 2σ) — для ROI-маркеров: ближе этого дублет
    выглядит одним пиком;
  - **якорный набор**, ΔE < 0.25·FWHM — для наборов, уходящих в библиотеку BecqMoni:
    пары от 0.25 до 0.85 FWHM разбирает там библиотечный фит по якорной линии, более
    далёкие — деконволюция, поэтому сливать их нельзя;
  - **вручную**, k×FWHM — грубое окно идентификации.

  Порог применяется ко всей группе (а не к соседней паре), иначе цепочка близких линий
  сцепляется в интервал шире порога. Объединённая линия получает интервал слитых линий
  «(E_min–E_max)», энергию-центроид по I и суммарную интенсивность.
- **Равновесие ряда**: пересчёт интенсивностей на один распад родителя ряда
  (Tl-208 ×0.3594, Po-212 ×0.6406; Th-227 ×0.9862, Fr-223 ×0.0138, Tl-207 ×0.99724).
- **Фильтры с выключателями** (интенсивность — относительная внутри изотопа или абсолютная;
  энергия; тип линий), сортировка (E, I, T½, нуклид), топ-N на нуклид, «скрыть невыбранные».
- **Поиск близких линий** по всей базе: энергия ± окно идентификации, фильтры I/T½ —
  поиск интерференций (классика: 186 кэВ → Ra-226 3.6 % / U-235 57.2 %).
- **Проверка перед сохранением**: линии с равными энергиями, нулевые выходы, перекрытие зон.
- **Экспорт — два формата** из одного набора линий:
  ROI-конфигурация (линии-маркеры как файлы «Intensities», зоны % от E или k×FWHM,
  зоны+маркеры; цвета по цепочке/семейству или по нуклиду) и **дописывание набора нуклидов
  (NuclideSet)** в ваш `NuclideDefinition.xml` — маркеры на спектре BecqMoni.

## Запуск

Открыть `index.html` в браузере — работает с `file://`, сеть не нужна (база встроена).
Или любой статический сервер:

```
python -m http.server 8642
```

## Экспорт в BecqMoni

**ROI-конфигурация** (`Скачать ROI .xml`): файл положить в `%APPDATA%\BecqMoni\config\ROI\`
(`C:\Users\<имя>\AppData\Roaming\BecqMoni\config\ROI\`) — конфигурация появится в списке ROI.
Коэффициенты Бк/cps в экспорте нулевые: они привязаны к кривой эффективности конкретного
детектора и задаются в самом BecqMoni.

**Библиотека нуклидов** (`Дописать набор в NuclideDefinition.xml…`): тот же набор линий
дописывается в **ваш** файл библиотеки как именованный **набор нуклидов (NuclideSet)** —
маркеры, которые BecqMoni подписывает на спектре. Выбираете свой
`%APPDATA%\BecqMoni\config\NuclideDefinition.xml`, скачивается его копия с добавленными
записями и набором; существующие нуклиды и наборы сохраняются, ничего не перезаписывается.
Галка «сохранить копию оригинала» (включена по умолчанию) дополнительно скачивает неизменённый
файл как `…backup-ГГГГММДД-ЧЧММ.xml`. Замену файла делать при закрытом BecqMoni. Формат:

```xml
<NuclideDefinitions>
  <Nuclide>
    <Name>Pb-214 (U-238)</Name>
    <Energy>351.932</Energy>
    <HalfLife>5.14487793748574E-05</HalfLife>  <!-- годы -->
    <NuclideColor>#E6821E</NuclideColor>
    <Note />
    <Visible>true</Visible>
    <Intencity>35.7237</Intencity>
    <Sets><guid>0f8b…-…</guid></Sets>          <!-- привязка к набору -->
    <IsAnchor>false</IsAnchor>                 <!-- true — ровно у одной линии набора -->
  </Nuclide>
</NuclideDefinitions>
<NuclideSets>
  <NuclideSet>
    <Id>0f8b…-…</Id>
    <Name>Мой набор</Name>
    <HideUnknownPeaks>false</HideUnknownPeaks>
  </NuclideSet>
</NuclideSets>
```

У нераспадных записей (ХРИ материалов, вторичные пики) `HalfLife = 0` — как в штатной
библиотеке BecqMoni (записи «x-rays», «Annihilation», «Tl-208 SE»).

### Якорная линия и полный набор

`IsAnchor=true` получает одна линия набора — **якорная**. Найдя её в спектре, BecqMoni
сажает остальные линии набора на табличные энергии и фитует их амплитуды (`LibraryPeakFitter`);
без якоря этот механизм не запускается вовсе. Автовыбор берёт сильную и при этом одинокую
линию — ту, у которой в пределах FWHM нет значимых соседей: для ряда Th-232 это 2614.5 (Tl-208),
для U-238/Ra-226 — 609.3 (Bi-214). Якорем можно вручную назначить любую **линию распада**:
ХРИ материалов и вторичные маркеры для этого не годятся — у первых интенсивность условная
(Kα1 = 100), у вторых положение задано эмпирической поправкой.

Сам `LibraryPeakFitter` допускает **несколько** якорных линий: он перебирает все записи с
`IsAnchor`, берёт сдвиг калибровки с сильнейшей по SNR и требует, чтобы с найденным пиком
совпала хотя бы одна (допуск 0,5·FWHM). Инструмент пока помечает ровно одну — если она
в спектре не нашлась, фит не стартует.

Галка **«полный набор (все линии, для фита)»** выгружает все γ- и X-линии выбранных нуклидов,
минуя галки, фильтры и объединение. Так и надо для библиотечного фита: по прогонам разработчика
BecqMoni полная цепочка ряда даёт recall 26/29 (Th-232) и 27/27 (Ra-226), тогда как набор из
одних сильных линий не добавляет к слепому поиску ничего. Вторичные пики в набор не попадают —
escape-компоненты BecqMoni строит сам.

Два условия, без которых связка амплитуд внутри бленда не работает:
- **интенсивности** — веса связанных линий берутся из `Intencity`, поэтому для рядов держите
  включённым «Равновесие ряда» (пересчёт на распад родителя);
- **имя** — цепочка определяется по родителю в скобках (`Bi-214 (Ra-226)`), поэтому нуклиды
  ряда добавляйте цепочкой или одним родительским изотопом, а не поштучно.

## Обновление базы данных

```
python update_nuclides.py            # пересборка из кэша data/raw/
python update_nuclides.py --refresh  # перекачать всё из API IAEA
```

Каталог нуклидов, семейства и цепочки — словарь `CAT` в начале скрипта: добавить нуклид =
добавить строку и перезапустить. API IAEA не отдаёт CORS-заголовков, поэтому страница ест
готовый снимок `data/nuclides.js`, а обновление выполняется скриптом.

**Обновление по кнопке**: вкладка *Actions* репозитория → workflow «Update nuclide DB from
IAEA» → «Run workflow». Экшен перекачивает базу из API, коммитит изменившийся снимок, и
GitHub Pages пересобирается автоматически. Тот же workflow гоняется по расписанию
1-го числа каждого месяца.

### Шпаргалка: добавление нуклида в каталог

```python
N("Ir-192", "192ir", 0, fam=("tech",))                 # обычный нуклид
N("Tc-99m", "99tc", 142.6836, fam=("med",))            # изомер: энергия уровня, кэВ
N("Ra-223", "223ra", 0, fam=("erh","med"), chain="u235")  # несколько семейств + цепочка
```

| Параметр | Что это | Пример |
|---|---|---|
| `имя` | отображаемое имя | `"Ir-192"`, `"Tc-99m"` |
| `api` | id нуклида в API IAEA: масса+символ строчными | `"192ir"`, `"99tc"` |
| `state` | энергия уровня материнского состояния, кэВ: `0` — основное, для изомера — энергия (допуск ±2 кэВ) | Tc-99m → `142.6836`, Pa-234m → `73.92`, Ag-108m → `109.44` |
| `fam` | семейства: `erh` / `med` / `fission` / `tech` / `naa` / `waste` (можно несколько) | `("erh","med")` |
| `chain` | членство в цепочке `u238`/`th232`/`u235` (порядок членов — в `CHAINS`) | `chain="u235"` |

Пороги базы — в шапке скрипта: `G_MIN_I` (γ ≥ 0.05 %), `X_MIN_I` (X ≥ 0.5 %), `E_MIN` (≥ 4 кэВ).
Нюанс: у Pu-238/239/240 и Cm-244 все γ-линии слабее 0.05 % — в базе от них только рентген;
для задач safeguards (Pu-239 129.3/375/413.7 кэВ) понизьте `G_MIN_I` до 1e-4 и перегенерируйте.

### Тонкости данных

- IAEA кладёт в γ-таблицу (`rad_types=g`) и рентген: у X-строк пустые поля
  `start/end_level_energy`. Обновлятор их отсекает (кроме аннигиляционной 511) —
  иначе линии дублируются с X-запросом.
- Изомеры (Tc-99m, Pa-234m, Ag-110m) выбираются по энергии уровня материнского состояния.
- Интенсивности — на 100 распадов излучающего нуклида (как в файлах «Intensities» BecqMoni).
- `HalfLife` в экспорте — в годах (конвенция BecqMoni), юлианский год 365.25 сут.

## Данные и источники

| Что | Источник |
|---|---|
| γ- и X-линии распада, T½, ветвления | [IAEA Live Chart of Nuclides API](https://nds.iaea.org/relnsd/vcharthtml/VChartHTML.html) (ENSDF) |
| ХРИ элементов (Kα/Kβ/L) | NIST X-Ray Transition Energies (Deslattes 2003), Bearden 1967 |
| Формулы вторичных пиков | Knoll, *Radiation Detection and Measurement*, **3-е изд., 1999, гл. 10** (комптон-край — разд. II.B, обратное рассеяние и пики вылета — разд. III, суммирование — III.E); Gilmore, *Practical Gamma-ray Spectrometry*, 2-е изд., гл. 2 и 10. Сверено по оригиналам, с главами и страницами — [`docs/REFERENCES-secondary-peaks.md`](docs/REFERENCES-secondary-peaks.md) |
| Поправки к положениям вторичных пиков | измерения комплекса Gamma-1C (NaI(Tl) 63×63, защита Pb 50 мм): комптон-край −0,8·FWHM, обратное рассеяние +10 кэВ |
| Формат ROI-конфигурации | исходники [BecqMoni](https://github.com/Am6er/BecqMoni) (`ROIConfigData.cs`, FormatVersion 120920) |
| Пороги слияния и требование якоря | `BecquerelMonitor/LibraryPeakFitter.cs`: `SparrowFwhm = 0.85`, `ClaimToleranceFwhm = 0.25`, гейт значимости Fisher z ≥ 4 |

## Дисклеймер

Неофициальный инструмент, не является частью BecqMoni. Интенсивности маркеров вторичных
пиков и ХРИ — условные (для визуальной идентификации, не для количественного анализа).
Проверяйте наборы линий по первоисточникам при ответственных измерениях.
