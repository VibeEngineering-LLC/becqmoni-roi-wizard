# Внесение модуля в BecqMoni через pull request

Как довести `integration/` до состояния, в котором его не стыдно предложить в
[`Am6er/BecqMoni`](https://github.com/Am6er/BecqMoni), и в каком порядке это делать.

Все факты об upstream проверены по репозиторию **25.07.2026**; где это важно, указано,
чем именно проверено.

## Коротко

PR — правильная форма передачи: копия папки в письме живёт до первого обновления
BecqMoni, PR живёт вместе с проектом. Но отправлять его «холодным» не стоит:
вклад великоват для сюрприза (11 файлов, 3075 строк, плюс 96 КБ данных), а область
пересекается с тем, что владелец правил на этой же неделе.

Порядок: **сначала issue с описанием и скриншотом → согласие на форму интеграции →
draft PR одной веткой → доводка по замечаниям.**

## 3. Лицензии

- Наш код — MIT, upstream — GPL-2.0. **MIT-код включается в GPL-проект без препятствий**:
  условия MIT (сохранить копирайт и текст лицензии) совместимы с GPL-2.0. Внутри BecqMoni
  файлы будут распространяться на условиях GPL-2.0 — это нормальный и ожидаемый исход.
- **Данные.** `nuclides.xml` — снимок IAEA Live Chart of Nuclides (ENSDF). В PR это стоит
  назвать явно: источник, дата снимка, скрипт пересборки. Атрибуция уже лежит в
  атрибутах корневого элемента (`Generated`, пороги интенсивности).
- Заимствований из кода BecqMoni в модуле нет: пороги (0.85 / 0.25 / z ≥ 4) — это числа,
  прочитанные из `LibraryPeakFitter.cs`, а не скопированный код.

## 4. Что доделать до отправки

- [ ] **Собрать в настоящей среде.** Проверка компиляции сделана в обход MSBuild
      (Roslyn + ручной набор файлов), потому что в системе нет targeting pack
      .NET Framework 4.8 — `MSBuild` останавливается с `MSB3644`. Для PR нужна честная
      сборка решения: поставить **.NET Framework 4.8 Developer Pack** (или VS с
      компонентом ".NET Framework 4.8 SDK"), открыть `BecquerelMonitor.sln`, добавить
      файлы и собрать. Пока это не сделано, в PR нельзя писать «собирается».
- [ ] **Открыть форму в дизайнере** — разметка собрана руками, и дизайнер VS может
      переставить порядок инициализации. Проверить, что после открытия/сохранения
      разметка не разъехалась.
- [ ] **Решить вопрос локализации** (см. §7): словарь `ApplyRussian()` против штатных
      `.resx`. Если владелец за `.resx` — включить `Localizable` и перенести подписи.
- [ ] **Пункт меню и его подписи** (см. §5).
- [ ] **Режим «полный набор»** — выгрузка всех линий минуя фильтры. В вебе он есть, в
      модуле нет, а именно он даёт лучший recall по прогонам разработчика (Th 26/29,
      Ra 27/27 против 16/14 у слепого поиска). Без него модуль хуже веб-версии в главном
      сценарии.
- [ ] **Несколько якорей.** Текущий `LibraryPeakFitter` перебирает все линии с
      `IsAnchor` и требует, чтобы совпал хотя бы один (допуск 0.5·FWHM). Модуль ставит
      ровно один — единственная точка отказа. Помечать 2–3 сильные и одинокие линии.
- [ ] **Прогон на реальном спектре** — хотя бы один: собрать набор мастером, открыть
      спектр, запустить library-fit, показать результат в PR. Это единственный аргумент,
      который в таком PR по-настоящему работает.

## 5. Как встраивается (точные места)

**`.csproj`** — добавить в существующий `ItemGroup` с `<Compile>`:

```xml
<Compile Include="RoiWizard\NuclideCatalog.cs" />
<Compile Include="RoiWizard\SpectralLine.cs" />
<Compile Include="RoiWizard\LineSetBuilder.cs" />
<Compile Include="RoiWizard\LineMerger.cs" />
<Compile Include="RoiWizard\SecondaryPeaks.cs" />
<Compile Include="RoiWizard\AnchorPicker.cs" />
<Compile Include="RoiWizard\ZoneCalculator.cs" />
<Compile Include="RoiWizard\SetChecker.cs" />
<Compile Include="RoiWizard\SetExporter.cs" />
<Compile Include="RoiWizard\RoiWizardForm.cs">
  <SubType>Form</SubType>
</Compile>
<Compile Include="RoiWizard\RoiWizardForm.Designer.cs">
  <DependentUpon>RoiWizardForm.cs</DependentUpon>
</Compile>
<EmbeddedResource Include="RoiWizard\nuclides.xml" />
```

Имя ресурса получится `BecquerelMonitor.RoiWizard.nuclides.xml` — оно и захардкожено в
`NuclideCatalog.ResourceName` (корневое пространство имён проекта — `BecquerelMonitor`).

**`tests/HostStubs.cs` в проект не добавлять** — там заглушки тех же типов, будет `CS0101`.

**Меню.** Образец — соседний пункт «Nuclide sets» (`MainForm.cs`):

```csharp
void NuclideSetToolStripMenuItem_Click(object sender, EventArgs e)
{
    this.ShowNuclideSetForm();
}

public void ShowNuclideSetForm()
{
    NuclideSetForm form = new NuclideSetForm(this);
    form.ShowDialog();
}
```

Для мастера — так же: объявить `RoiWizardToolStripMenuItem` в `MainForm.Designer.cs`
рядом с `NuclideSetToolStripMenuItem` (:878), обработчик в `MainForm.cs`, подписи —
в `MainForm.resx` и `MainForm.ru.resx` (ключ `RoiWizardToolStripMenuItem.Text`; в ru.resx
подписи соседних пунктов лежат так же, например :303).

Разрешение детектора передаётся конструктором `RoiWizardForm(Func<double>)`; если брать
неоткуда — конструктор без аргументов, тогда кнопка «из спектра» просто выключена.

## 6. Порядок

1. **Issue** в `Am6er/BecqMoni`: что за инструмент, зачем (ROI-конфигурации и наборы
   для library-fit собираются руками), скриншот формы, ссылка на живую веб-версию,
   объём вклада и вопрос по форме интеграции. Одна страница, без кода.
2. **Ответ владельца** — форма окна, локализация, нужен ли снимок данных в репозитории.
3. **Форк + ветка `feat/roi-wizard`**, коммиты по смыслу: (а) ядро и данные, (б) форма,
   (в) пункт меню и ресурсы, (г) тесты. Один PR — дробить нечего: без формы ядро мертво,
   без ядра форма не собирается.
4. **Draft PR** с описанием: что делает, откуда числа (`LibraryPeakFitter.cs` —
   0.85 / 0.25 / z ≥ 4), откуда данные (IAEA/ENSDF, скрипт пересборки), как проверялось
   (71 тест, `run_tests.cmd`, код возврата 0/1).
5. **Доводка** по замечаниям, снятие статуса draft.

## 7. Вопросы владельцу

1. **Локализация.** Подписи формы накладываются словарём `ApplyRussian()` по текущей
   культуре, а не `.resx`. Сделано так намеренно (координаты контролов в ресурсах ради
   двух языков — дорого), но это расходится с конвенцией проекта. Оставить или
   перевести на `.resx`?
2. **Снимок данных в репозитории.** 96 КБ XML внутри сборки — приемлемо, или каталог
   должен подтягиваться из `NucBase`, который в BecqMoni уже есть?
3. **Обновление каталога.** Сейчас — python-скрипт по IAEA Live Chart. Нужен ли он в
   дереве проекта или достаточно готового снимка?
4. **Якоря.** Помечать несколько якорных линий вместо одной — согласуется ли это с тем,
   как задуман гейт в `LibraryPeakFitter`?
5. **Форма окна.** Три вкладки (изотопы → линии → оформление и экспорт) против одного
   окна с секциями — что ближе к тому, как устроен остальной интерфейс.
